## UI 2026-10-10: ช่วงที่จบที่วันล่าสุด — วาดให้เสมอ + ป้าย "missing" สีแดง (ใหม่)

### ปัญหาเดิม (ตัวอย่างจริง)

ใส่ `21/08/2026 → 09/10/2026` แล้วโดนปฏิเสธทั้งคู่ — คลังเส้นโค้งของต้นทางไม่รับเพราะวันเริ่ม
ห่างจากเส้นโค้งที่ใกล้สุด (09/09/2026) ถึง 19 วัน ส่วนคลังรายสัปดาห์มีถึงแค่วันอาทิตย์ 04/10/2026
วันที่จบจึง "นอกคลัง" — จบด้วยข้อความ unavailable ไม่วาดอะไรเลย ทั้งที่อีกนิดเดียวก็ได้
และที่แย่กว่านั้นคือ ท่าทางธรรมดาที่สุด — **ลากดินสอไปจนสุดขอบขวาของกราฟ** — จบที่วันล่าสุด
เสมอ ซึ่งเลยเส้นโค้งใหม่สุดของทั้งสองคลังไป 1-6 วัน เท่ากับว่าท่านี้โดนปฏิเสธเกือบทุกครั้ง

### กติกาใหม่

- **ปลาย "จบ" ที่เลยเส้นโค้งใหม่สุดของคลังที่ตอบ ยังตอบให้** ถ้าเลยไปไม่เกิน **7 วัน** — วาดจาก
  เส้นโค้งใหม่สุดที่มี แล้ววันที่ที่เลยไปโผล่เป็น**ป้ายสีแดง** ข้างแถวปุ่ม cost basis:
  `missing 05/10/2026 – 09/10/2026` (วันเดียวพิมพ์ `missing 10/10/2026`) — ชี้เมาส์ค้างดูได้
  คำอธิบายเต็ม
- ตัวอย่างเดิมด้านบนตอนนี้ได้ทันที: `21/08/2026 → 09/10/2026` → วาดหน้าต่าง
  **23/08/2026 → 04/10/2026** (จากคลังรายสัปดาห์) + ป้ายแดง `missing 05/10/2026 – 09/10/2026`
- ที่เลยเกิน 7 วันยัง**ปฏิเสธเหมือนเดิม** พร้อมข้อความเดิม — 7 วันคือเพดานที่คลังรายสัปดาห์
  ห่างจากวันนี้ได้มากสุด (วันอาทิตย์ + ไม่เกิน 6 วัน) ท่า "ลากไปขอบขวาสุด" จึงไม่โดนปฏิเสธอีก
- **ปลาย "เริ่ม" ไม่มีข้อยกเว้น** — ของใหม่มาที่ปลายใหม่เท่านั้น ปลายเก่าไม่มีเรื่องราวแบบนี้
- ป้ายแดงหายเองเมื่อหน้าต่างที่วาดอยู่จบที่เส้นโค้งจริง (กดปุ่มสำเร็จรูปแล้วป้ายหายทันที)
  และไม่มีตอนปฏิเสธ — ป้ายมาจากผลลัพธ์ที่วาดจริง จึงค้างเก่าไม่ได้
- สองคลังยังแยกกันเหมือนเดิม ไม่ผสมข้ามคลัง — ป้ายแดงพูดถึงคลังที่ตอบจริงเท่านั้น
- เบราว์เซอร์เช็คช่วงวันที่ในเครื่อง (โหมดไม่ต่อ API) ก็ใช้เพดานเดียวกัน — วันที่จบที่รับได้
  ตรงกันทั้งสองโหมด (มี probe ตรวจทั้งคู่)

## UI 2026-10-03: ตา volume, วันที่ วว/ดด/ปปปป, ดินสอลากเลือกช่วง (ใหม่)

### ไอคอนตา 👁 ของแท่ง volume ด้านล่าง (ใหม่)

- ปุ่มตาข้าง**ช่องเลือกแหล่ง volume** — ซ่อน/แสดงแท่ง volume ด้านล่างของกราฟ
  (คนละอันกับตาข้าง "Profile window" ซึ่งคือ profile ขอบขวา และคนละอันกับตา ETF flows)
- จำค่าไว้ (`vsa_layer_visible_volume`) — ซ่อนแล้วช่องเลือกแหล่งยังกดได้แต่จางลง
  และแถบสถานะต่อท้ายด้วย `— hidden` ตัวเลข breakdown และแถว hover ยังอยู่ครบ
  (ซ่อนแค่การวาด ไม่ได้เลิกโหลดข้อมูล) — ใช้เวลาอยากดูแท่งเทียนกับ cost basis เฉยๆ

### วันที่แบบวันขึ้นก่อน (วว/ดด/ปปปป) ทั้งหน้า

- เปลี่ยนทุกที่ที่แสดงวันที่: แถบสถานะ, แถว hover, การ์ด Who Moved, holder panel,
  ป้ายบนเส้นราคาของกราฟ (`cost-basis vintage 03/10/2026`), ข้อความไทย/อังกฤษในท้ายหน้า, ป้าย AUDITED
- **ช่องวันที่สองช่องของ cost basis ตอนนี้เป็นช่องพิมพ์เอง** (วว/ดด/ปปปป เช่น `24/08/2026`)
  — **ไม่มีปฏิทินป๊อปอัป** เพราะช่องวันที่ของเบราว์เซอร์แสดงรูปแบบตามภาษาของเบราว์เซอร์ กำหนดเองไม่ได้
  พิมพ์ `24/8/2026` (ไม่ต้องเติมศูนย์) หรือ `2026-08-24` ก็ได้ ระบบอ่านได้ทั้งคู่
- **ที่เก็บและที่ส่งให้ API ยังเป็น ISO (YYYY-MM-DD) เหมือนเดิม** — เปลี่ยนแค่ตอนแสดงผล หน้าจึงยัง
  ให้ผลตรงกับ API ทีละฟิลด์เหมือนเดิม (มี probe ตรวจทุกครั้งที่แก้โค้ด)
- **ไม่มี min/max ของปฏิทินคอยกันแล้ว** — แทนด้วยการตรวจตอนกด Apply: คู่วันที่อยู่นอกช่วงที่คลังจริง
  มี ระบบจะบอกช่วงที่ตอบได้ตรงๆ (เช่น `01/01/2016 → 03/10/2026`) ไม่เงียบๆ เอาหน้าต่างอื่นมาแทน

### ปุ่มดินสอ 🖉 — ลากบนกราฟเลือกช่วง cost basis (ใหม่)

- อยู่ถัดจากปุ่ม Apply ในแถว cost basis — กดแล้วเคอร์เซอร์เป็นกากบาท **กดค้างแล้วลาก** บนกราฟ
  จะเห็นแถบสีน้ำเงินพร้อม**วันที่สองวันที่จะได้**กำกับอยู่บนแถบ; ปล่อยเมาส์ = ใช้ช่วงนั้นทันที
- ถ้าลากครอบแค่วันเดียว (หัวท้ายเป็นวันเดียวกัน) จะมีข้อความบอกให้ลากให้กว้างอย่างน้อยสองวัน
  แล้วรอต่อ — ยังไม่หลุดโหมด; กดดินสอซ้ำหรือกด `Esc` = ยกเลิก ไม่เปลี่ยนอะไร
- **เมาส์เท่านั้น** — บนจอสัมผัส การลากคือการเลื่อนกราฟ ระบบจึงไม่แย่งท่าทางนี้
  (มือถือเลือกช่วงเองได้ด้วยการพิมพ์วันที่ตามปกติ)
- คู่ที่ได้จากการลากเดินผ่านทางเดียวกับปุ่ม Apply (ตรวจค่า + เก็บ ISO + เทียบช่วงคลัง)
  — ตัวเลขจึงไม่มีทางต่างจากพิมพ์เอง; เลือกช่วงบนสุดท้ายที่ต้นทางตอบไม่ได้ก็ยังขึ้นคำปฏิเสธในแถบสถานะ

## ⚡ ทางลัด: ดับเบิลคลิกไฟล์เดียว

ดับเบิลคลิก **`D:\refresh-and-publish.bat`** (อยู่ที่รากไดรฟ์ D: ตรงๆ) — มันรันสองขั้นตอน
ในหัวข้อถัดไปให้เองทั้งหมด (refresh → publish ขึ้น GitHub Pages) ไม่ต้องพิมพ์คำสั่งเอง

- **จบที่ publish ไม่เปิดเซิร์ฟเวอร์ local** (สั่ง `--no-launch` ให้) — เสร็จแล้วเปิดหน้าเว็บจริง
  ที่ https://noareyenoar.github.io/BTC_True_Volume/ รอ Pages redeploy อีก ~1-2 นาที
- **หน้าต่างจะเงียบและดูเหมือนค้าง — ไม่ได้แฮงก์** ขั้น 1 ใช้เวลา 2-10 นาที (ปกติ ~2 นาทีถ้าเพิ่งรันไป)
  ปล่อยไว้ ห้ามปิดหน้าต่าง
- **จบแล้วมันจะหยุดรอ "Press any key to continue . . ."** — กดอะไรก็ได้เพื่อปิด
  (หยุดรอทั้งตอนสำเร็จและตอนพัง เพื่อให้อ่านข้อความได้ทัน)
- **พังแล้วหยุดทันที** — ขึ้น `FAILED` และ**ไม่**ไปต่อขั้น 2 (ไม่ publish ของที่พัง) ข้อความ error
  อยู่เหนือขึ้นไป รันซ้ำได้ปลอดภัย เพราะทั้งสองขั้นทำต่อจากเดิม ไม่ได้เริ่มใหม่หมด
- **ส่ง flag เพิ่มได้** แต่ต้องสั่งจาก cmd (ไม่ใช่ดับเบิลคลิก) เช่น
  `D:\refresh-and-publish.bat --force-probe` — flag ถูกส่งต่อไปทั้งสองขั้น (`--no-push` = อัปเดต
  เว็บในเครื่อง + commit แต่ยังไม่ push) ถ้าพิมพ์ flag ผิด ขั้น 1 จะหยุดทันทีและไม่ publish
- ในไฟล์เป็นภาษาอังกฤษล้วนโดยตั้งใจ — cmd.exe อ่านไฟล์ .bat แบบ byte ไม่ปลอดภัยกับภาษาไทย
  คำอธิบายภาษาไทยจึงอยู่ที่นี่

## สิ่งที่เปลี่ยนไป (ต้องรู้)

- **Run แรกหลังอัปเดต** (~7 นาที): สร้าง cache ไฟล์ 2 ไฟล์
  - `raw/triple_gate_adjudicated.json` — ผลตรวจ disputed days 21 วัน (BTC 11 + ETH 10)
  - `raw/vision_metrics_holes.json` — 373 วันที่ Binance ไม่เคย publish (2020-11-23 → 2021-11-30)
- **Run ต่อมา** (~1-3 นาที): จะเห็น log `"N disputed days skipped (tape fingerprint unchanged)"` และ `"N days skipped (cached holes)"` — หมายถึงข้ามงานซ้ำซ้อนได้แล้ว จบด้วย `data through <ล่าสุด>` (Vision ล่าช้า ~1 วัน)
- **ราคาวันนี้ไม่ต้องรันเลย** — หน้าเว็บดึงราคา real-time จาก Binance เองในเบราว์เซอร์ (ราคา + ปริมาณเบื้องต้น ⚠ LIVE)
- **เปิดหน้าเข้ามาจะเริ่มที่ TF `1d`** (เดิม `1h`) — มองภาพรวมก่อน แล้วค่อยกด `1h` ลงรายละเอียด ค่าเริ่มต้นนี้มาจาก API (`/api/symbols` → `default_interval`) ไม่ได้ฝังไว้ในหน้าเว็บ
- **Flag เพิ่มเติม** สำหรับงาน audit (ไม่ต้องรันปกติ):
  - `.venv\Scripts\python.exe BTC_True_Volume\refresh_before_visualizer.py --force-adjudicate` — บังคับตรวจ disputed days ใหม่กับ Binance Vision (~4.5 นาที)
  - `... --force-probe` — บังคับ probe earliest + holes ใหม่
  - `... --force-adjudicate --force-probe` ใช้คู่กันได้ตามปกติ
  - `... --backfill-cb` — ดึงคลังเส้นโค้งรายสัปดาห์ให้ครบทุกวัน (ทำไปแล้วครั้งเดียว 2026-09-20: 560 วัน ใช้เวลา ~740 วินาที) **ปกติไม่ต้องรันซ้ำ** ขั้นตอนนี้อยู่ในข้อ 1 แล้ว — รันปกติจะเช็คใหม่แค่วันล่าสุด 3 วัน
- **Cost basis + holder cohorts** — ไม่มีคำสั่งใหม่ให้รัน ขั้นตอนนี้อยู่ในข้อ 1 แล้ว
  - **ตอนนี้ดึงจากเว็บ live ของ checkonchain** (`charts-cdn.checkonchain.com`) ไม่ใช่ mirror บน GitHub ที่หยุดไปตั้งแต่ 2026-02-19 อีกแล้ว — ข้อมูลจึง**สดถึงวันล่าสุด** (2026-09-20) ไม่ใช่ค้างอยู่ที่ 2026-02-19 เหมือนก่อนหน้านี้
  - บนกราฟมีชั้น cost-basis อยู่ที่**ขอบขวา** (เดิมอยู่ซ้าย ตอนนี้ย้ายมารวมกับ profile แล้ว) เทียบ 2 วันให้เห็นพร้อมกัน:
    - **เส้นโปร่ง (hollow)** = supply ที่ราคานั้น ณ วันแรกของหน้าต่าง
    - **แท่งทึบ (filled)** = supply ที่ราคานั้น ณ วันสุดท้าย
    - **ฝา (cap)** ระหว่างปลายทั้งสอง = ส่วนที่เปลี่ยน — เขียว = มีคนเก็บเพิ่มที่ราคานั้น, แดง = ถูกขาย/ย้ายออก ทั้งสามอย่างใช้สเกลเดียวกัน ความยาวฝา = จำนวน BTC ที่เปลี่ยนจริง
    - เลือกหน้าต่างได้ **30/90/180/365 วัน + 4 ปี** (ค่าเริ่มต้น **30 วัน**) แยกจาก Profile window
      - **4y (ใหม่ 2026-09-20)** = 2022-06-18 → วันล่าสุด รวม ~4.3 ปี — อันนี้**คำนวณเอง**จากเส้นโค้งที่เก็บไว้ เพราะต้นทางไม่เคยทำหน้าต่างนี้ (ไม่มี `urpd_diff_1460` upstream) ตัวเลขจริง แต่มีข้อจำกัด: เส้นโค้งปี 2022 ของต้นทางตัดแกนไว้ที่ **$68,000** ดังนั้นโซนที่ราคาสูงกว่านั้นจะเห็นเป็น "ของเข้าวันนี้" ทั้งก้อน (ไม่มี "เมื่อก่อน" ให้เทียบ) — status bar จะพิมพ์เตือนไว้ทุกครั้งที่เลือก 4y
      - **14d / 60d / 120d ไม่มีให้เพิ่ม** — เช็คกับต้นทางสดแล้ว (2026-09-20): 14d ถูกปลดไปแล้ว, 60d/120d ไม่เคย publish (มีแต่สำเนา 60d ค้างจาก mirror ก.พ. 2026 ที่เป็น variant `_realized` คนละตัววัด) ส่วนหน้าต่างวันที่ตรึงของต้นทางที่มีจริงคือ 2024-11-01 กับ 2025-03-01 — ตอนนี้**ใส่เป็นช่วงวันที่เองได้แล้ว** ไม่ต้องรอเพิ่มปุ่ม
      - **หน้าต่าง 14 วันถูกถอดออกแล้ว** — ต้นทางปลดไปแล้ว จึง 404 บนเว็บ live ถ้าเบราว์เซอร์เคยจำ 14 วันไว้ ระบบจะ fallback มาที่ค่าเริ่มต้น (30 วัน) ให้เอง

        - ข้อมูลมี **สองคลัง** และระบบเลือกเองจากวันที่ที่ใส่ (แก้ 2026-09-26):

    2. `node BTC_True_Volume\probe_dates.js` — ตรวจช่องวันที่พิมพ์เอง (การอ่าน วว/ดด/ปปปป, วันผิดปฏิทิน เช่น 31/02, ช่วงนอกคลังถูกปฏิเสธพร้อมบอกช่วง, คู่ที่ใช้ได้ถูกเก็บเป็น ISO และช่องกลับมาเป็น วว/ดด/ปปปป) ต้องขึ้น `all date checks pass`
    3. `.venv\Scripts\python.exe BTC_True_Volume\probe_dated_server.py` แล้ว `node BTC_True_Volume\probe_dated_pair.js` — ตัวแรกดัมพ์คำตอบของ API 6 กรณี ตัวหลังรัน `app.js` ตัวจริงใน node (ไม่ใช้เบราว์เซอร์) เทียบกับคำตอบนั้นทีละฟิลด์ ต้องขึ้น `all scenarios identical` (หมายเหตุ: คู่วันที่ใน probe ถูก **derive จากคลังปัจจุบัน** อัตโนมัติ — คลังเส้นโค้งของต้นทางหมุนไปทุกครั้งที่ refresh ถ้าเขียนวันตายตัวไว้ probe จะกลายเป็นตรวจแต่เส้นทางปฏิเสธโดยไม่รู้ตัว)
    4. ตรวจของที่**เผยแพร่แล้ว**จริง: ดาวน์โหลด `manifest.json` กับ `cost_basis/BTC_dated.json.gz` จาก https://noareyenoar.github.io/BTC_True_Volume/ มาวางในโฟลเดอร์ชั่วคราวโดย**คงโครงเดิม** (manifest.json อยู่ราก, ไฟล์ .gz อยู่ในโฟลเดอร์ `cost_basis`) แล้วรันข้อ 3 ซ้ำโดยใส่ `PROBE_SITE=โฟลเดอร์นั้น` — จะเห็นว่าหน้าที่เปิดอยู่จริงให้ตัวเลขเดียวกับเครื่องเรา

## ETF flows (ใหม่ 2026-09-23)

แท่งเขียว/แดงที่ซ้อนอยู่ใน**กราฟราคา** (อยู่เหนือแท่ง volume ในกรอบเดียวกัน) คือ
**กระแสเงินสุทธิรายวันของกองทุน spot BTC ETF สหรัฐฯ เป็นดอลลาร์** (creations − redemptions)
— ตอบคำถามว่า "วันนั้นมีเงินเข้า/ออกเท่าไร" ซึ่งเป็นคนละคำถามกับราคาและคนละหน่วยกับ volume

- **ที่มา**: chart `btconchain/etfs/etf_flowsvsprice` (trace `ETF Net Flow [USD]`) บน CDN
  เดียวกับที่ดึง cost basis อยู่แล้ว เก็บลง `checkonchain_series.parquet` ผ่าน
  `fetch_checkonchain_urpd.py` — **ไม่มีคำสั่งใหม่ให้รัน** อยู่ในขั้นตอนที่ 1 อยู่แล้ว
- **หน่วยเป็นดอลลาร์ ไม่ใช่ BTC** — ห้ามเทียบแท่งต่อแท่งกับเลเยอร์ที่เป็น BTC (volume, cost basis)
- **เริ่ม 2024-01-11** (วันซื้อขายวันแรก) ถึงวันล่าสุด — ปัจจุบัน 987 วัน (401 วันเงินเข้า /
  275 วันเงินออก / 311 วันตลาดปิด)
- **วันเสาร์-อาทิตย์และวันหยุดตลาดสหรัฐฯ = 0** ซึ่งหมายถึง **"ตลาดไม่เปิด" ไม่ใช่ "ไม่มี flow"**
  — hover จะขึ้น `no US session (weekend/holiday)` ให้อ่านออก ห้ามอ่านเป็นสัญญาณขาลง
- **วันล่าสุดเป็นค่าชั่วคราว** — ต้นทางเพิ่งเริ่มสะสมข้อมูลของวันนั้น (วัด 2026-09-23: วันล่าสุด
  2026-09-23 = 0 แต่ 2026-09-22 = +$615.70M) อย่าสรุปอะไรจากแท่งของ "วันนี้" ให้ดูวันที่ซื้อขาย
  ล่าสุดจากแถบสถานะ (`ETF flows +$… · YYYY-MM-DD (last session)`)
- **hover ที่แท่งเทียน** จะขึ้นแถว `ETF net flow (USD)` ของวันนั้น
  - ก่อน 2024-01-11 → `n/a — series starts 2024-01-11`
  - วันตลาดปิด → `no US session (weekend/holiday)`
- **ตา 👁 ข้างคำว่า "ETF flows (USD)"** กดเพื่อซ่อน/แสดงแท่งนี้ (จำค่าไว้ที่ `vsa_layer_visible_etf`)
  ซ่อนแล้วแถวใน hover หายไปด้วย แต่ตัวเลขในแถบสถานะยังอยู่ (ต่อท้ายด้วย `— hidden`)
- **ที่ TF 1h แท่งจะกว้างแค่ 1 ชั่วโมง** (1 แท่ง = 1 วัน) เป็นข้อจำกัดของวิธีวาดด้วย histogram
  อ่านง่ายสุดที่ TF `1d` ซึ่งเป็นค่าเริ่มต้นอยู่แล้ว
- **บนเว็บที่แชร์** ข้อมูลชุดนี้ถูกฝังมากับหน้าเว็บเป็น `site/etf/BTCUSDT.json` — ไม่ต้องดึงอะไร
  เพิ่มตอนเปิดหน้า ส่วน **ETHUSDT ไม่มีปุ่มนี้** (ซ่อนไปเลย) เพราะชุดข้อมูลนี้เป็น ETF ของ BTC
  เท่านั้น ไม่มีคู่ ETH และไม่ใช้เป็น proxy
- ตรวจสอบอัตโนมัติใน `verify_all.py` (ขั้น `etf_flows`): 987 วันเรียงต่อกันไม่ขาด, ทุกค่าตรงกับ
  ไฟล์ HTML ที่ cache ไว้ (worst |diff| = 0), และไฟล์ที่ขึ้นเว็บตรงกับ store ทุกจุด
